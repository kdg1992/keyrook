Überblick

Was Keyrook ist

Keyrook verwaltet Zugangsdaten für Websites, FTP/SFTP, E-Mail-Postfächer, Hosting-Panels, Server, SSH-Schlüssel, Domains und beliebige eigene Datensätze in einer verschlüsselten Datei (.keyrook). Die Datei liegt dort, wo Sie sie speichern: auf der Festplatte, einem Netzlaufwerk oder in einem synchronisierten Ordner. Es gibt keinen Server, kein Konto und keine Cloud.

Keyrook richtet sich an Menschen, die viele Kunden, Projekte und Server betreuen: Einträge lassen sich Kunden und Projekten zuordnen, mit Tags versehen, nach Ablaufdatum überwachen und per Kundenbericht übergeben. Die Oberfläche ist auf Tastaturarbeit ausgelegt: Suchen, Kopieren und Verbindungsbefehl in einem Zug.

Sicherheitsprinzipien

  • Starke, geprüfte Kryptographie. Das Masterpasswort wird mit Argon2id zu einem Schlüssel abgeleitet; der Tresor ist mit AES-256-GCM verschlüsselt und authentifiziert. Jede Veränderung der Datei wird beim Öffnen erkannt.
  • Optionaler zweiter Faktor. Eine Schlüsseldatei mit 32 zufälligen Bytes kann zusätzlich zum Passwort verlangt werden.
  • Atomares Speichern. Jede Änderung wird vollständig oder gar nicht geschrieben. Konflikte mit einer gleichzeitig geänderten Datei werden erkannt.
  • Sperren statt Vertrauen. Keyrook sperrt nach Inaktivität, bei Bildschirmsperre und Standby des Systems, wahlweise beim Minimieren oder Fokusverlust, und jederzeit mit Strg+L.
  • Kontrollierte Zwischenablage. Kopierte Werte werden nach einer einstellbaren Zeit (Standard 20 Sekunden) und beim Sperren wieder gelöscht.
  • Backups eingebaut. Automatische verschlüsselte Backups mit Aufbewahrungsregeln, Wiederherstellung mit Vorschau und eine schreibgeschützte Integritätsprüfung.

Was Keyrook nicht tut

Keyrook sendet keine Daten ins Netz, mit zwei Ausnahmen, die beide ausdrücklich von Ihnen ausgelöst werden: die Update-Prüfung (fragt die Release-Liste auf GitHub ab) und der Abgleich mit bekannten Datenlecks (sendet die ersten 5 Zeichen eines SHA-1-Hashes je Passwort an den Dienst Have I Been Pwned, nach einer Rückfrage bei jedem Durchlauf). Keyrook lädt keine Updates herunter, installiert nichts selbst, öffnet keine SSH-Verbindungen und erhebt keine Nutzungsdaten.

Grenzen

Keyrook wurde nicht unabhängig auditiert. Die Installer sind nicht signiert. Angezeigte oder bearbeitete Werte liegen als Java-Zeichenketten im Speicher und lassen sich dort nicht zuverlässig löschen. Zwischenablage-Verläufe des Betriebssystems oder Clipboard-Manager können Kopien behalten, die Keyrook nicht entfernen kann. Auf Linux-Desktops erreichen Sperr- und Standby-Ereignisse Java meist nicht; dort greifen der Inaktivitätstimer und die Fensterregel.

Installation

Download und Prüfsumme

Laden Sie Installer nur von der Release-Seite des Projekts: https://github.com/kdg1992/keyrook/releases/latest. Jeder Release enthält die Datei SHA256SUMS.txt. Vergleichen Sie vor der Installation den SHA-256-Wert der heruntergeladenen Datei mit der zugehörigen Zeile:

sha256sum --ignore-missing -c SHA256SUMS.txt        # Linux
shasum -a 256 Keyrook-*.dmg                         # macOS, Wert manuell vergleichen
Get-FileHash .\Keyrook-*.msi -Algorithm SHA256      # Windows PowerShell, Wert manuell vergleichen

Es gibt Pakete für Windows x64 (MSI), macOS mit Apple Silicon (DMG) und Linux x64 (DEB, RPM). Für Linux ARM64 und Intel-Macs gibt es keine Builds.

Windows

  1. MSI doppelklicken. Die Installation erfolgt pro Benutzer in %LOCALAPPDATA%\Keyrook, ohne Administratorrechte. Der Zielordner kann im Installer geändert werden.
  2. Zeigt SmartScreen „Unbekannter Herausgeber“, prüfen Sie zuerst Downloadquelle und Prüfsumme. Danach erlaubt Weitere Informationen → Trotzdem ausführen diesen einen Installer. Deaktivieren Sie keine systemweiten Schutzfunktionen; Unternehmensrichtlinien oder Smart App Control können die Ausnahme verhindern.
  3. Ein Update wird einfach über die bestehende Version installiert.

macOS

  1. DMG öffnen und Keyrook.app in den Ordner Programme ziehen.
  2. Die App ist nicht notarisiert. Nach dem ersten Öffnungsversuch erlaubt Systemeinstellungen → Datenschutz & Sicherheit → Dennoch öffnen eine Ausnahme für genau diese App. Gatekeeper nicht global abschalten.
  3. Ein Update ersetzt die App im Programme-Ordner.

Linux (DEB, RPM)

sudo apt install ./Keyrook-<Version>-linux-x64.deb      # Debian, Ubuntu und Abkömmlinge
sudo dnf install ./Keyrook-<Version>-linux-x64.rpm      # Fedora, RHEL und Abkömmlinge

Die Anwendung liegt danach unter /opt/keyrook/bin/Keyrook und erscheint im Anwendungsmenü unter „Dienstprogramme“. Auf Systemen ohne Desktop-Menüverzeichnis (Server, Container, WSL) läuft die Installation durch; es gibt dann nur keinen Menüeintrag. Ein Update wird über die alte Version installiert; die Pakete sind nicht von einem Distributions-Repository signiert.

Arch Linux, CachyOS und portables Archiv

Jeder Release enthält zusätzlich das Archiv Keyrook-<Version>-linux-x64.tar.gz (das fertige Anwendungsabbild samt Java-Laufzeit) und ein PKGBUILD für pacman-basierte Distributionen wie Arch Linux, CachyOS, Manjaro oder EndeavourOS:

mkdir keyrook-bin && cd keyrook-bin
curl -LO https://github.com/kdg1992/keyrook/releases/latest/download/PKGBUILD
makepkg -si      # lädt das Archiv, prüft die SHA-256 und installiert das Paket keyrook-bin

Das Paket installiert nach /opt/keyrook, legt /usr/bin/keyrook und einen Menüeintrag an und wird mit pacman -Rns keyrook-bin wieder entfernt. Das Archiv allein läuft auf jedem x64-Linux mit den üblichen Desktop-Bibliotheken: entpacken und Keyrook/bin/Keyrook starten, ohne Installation.

Updates

Keyrook lädt keine Updates herunter und installiert keine. Info → Nach Updates suchen fragt einmal bei GitHub nach dem neuesten veröffentlichten Release und zeigt an, ob Ihre Version aktuell ist, mit den Release-Notizen als Text und einem Button zur Release-Seite. Unter Einstellungen kann Beim Start automatisch nach Updates suchen eingeschaltet werden (Standard: aus); dann erscheint beim Start ein Hinweis, falls eine neuere Version existiert.

Zum Aktualisieren: Tresor sichern, Installer herunterladen, Prüfsumme vergleichen, über die bestehende Version installieren. Tresore und Einstellungen sind eigene Dateien und bleiben erhalten. Seit Version 1.5.0 schreibt Keyrook das Dokumentformat 3 mit höheren Grenzen (Abschnitt 2.7). Aktualisieren Sie deshalb alle Rechner, die denselben Tresor öffnen, gemeinsam.

Umstieg von Version 1.4 und älter

Ein Tresor aus Keyrook 1.4 oder älter öffnet sich unverändert; ein Hinweis über der Liste sagt, dass er beim nächsten Speichern umgewandelt wird. Vor diesem ersten Speichern legt Keyrook die unveränderte alte Datei im selben Ordner als <Tresor>.schema-v2-r<Revision>.keyrook.bak ab (bei Tresoren aus 0.7 oder älter schema-v1) und nennt den Namen einmal. Ältere Keyrook-Versionen können den umgewandelten Tresor nicht mehr öffnen; sie lehnen ihn ab, ohne ihn zu verändern. Der Weg zurück ist die abgelegte Kopie: in .keyrook umbenennen und mit der älteren Version öffnen. Änderungen nach der Umwandlung sind darin nicht enthalten. Löschen Sie die Kopie, sobald alle Rechner aktualisiert sind und der Tresor wie erwartet funktioniert.

Erste Schritte

Tresor anlegen

  1. Keyrook starten. Das Entsperrformular erscheint. Wählen Sie eine neue Datei mit der Endung .keyrook; eine vorhandene Datei wird beim Anlegen nie überschrieben.
  2. Masterpasswort zweimal eingeben. Ein nicht übereinstimmendes zweites Passwort wird unter dem Feld angezeigt.
  3. Optional eine Schlüsseldatei wählen (siehe unten) und die Argon2-Kosten anpassen.
  4. Anlegen bestätigen. Der Tresor ist sofort geöffnet.
Empfehlung

Verwenden Sie ein langes Masterpasswort oder eine Passphrase, die Sie nirgends sonst benutzen. Es gibt keine Wiederherstellung: Wer Passwort (und ggf. Schlüsseldatei) verliert, verliert den Tresor. Richten Sie direkt nach dem Anlegen einen Backup-Ordner ein (Kapitel 9).

Schlüsseldatei

Eine Schlüsseldatei enthält genau 32 Bytes und wird beim Entsperren zusätzlich zum Passwort benötigt. Daten → Schlüsseldatei erzeugen schreibt 32 kryptographisch zufällige Bytes in eine neue Datei mit privaten Rechten. Der gewählte Dateiname darf kein symbolischer Link sein. Bewahren Sie eine getrennte, sichere Kopie auf: ohne diesen Faktor ist der Tresor unwiederbringlich verloren. Das Erzeugen allein ändert keinen bestehenden Tresor; zugeordnet wird die Datei beim Anlegen oder über Passwort / Schlüsseldatei ändern (Abschnitt 9.6).

Beim Entsperren können Sie Schlüsseldatei für diesen Tresor merken ankreuzen. Dann wird nur der Pfad der Datei in den Einstellungen gespeichert und beim nächsten Entsperren vorbelegt, niemals ihr Inhalt. Die Option ist standardmäßig aus; ein Entsperren ohne Häkchen vergisst den Pfad wieder.

Argon2-Einstellungen

Argon2id macht das Ausprobieren von Passwörtern teuer. Beim Anlegen und später über Daten → Argon2-Einstellungen wählen Sie Speicher (65536 bis 262144 KiB), Iterationen (1 bis 5) und Parallelität (1 bis 16 Lanes; der Speicher muss durch das Vierfache der Lanes teilbar sein). Eine Änderung verschlüsselt den Tresor atomar neu und legt vorher das konfigurierte Backup an. Höhere Werte verlängern jedes Entsperren und jede Integritätsprüfung; auf Rechnern mit 4 GiB Arbeitsspeicher bleibt der Standard sinnvoll.

Entsperren und Sperren

Das Entsperrformular ist mit dem zuletzt geöffneten Tresorpfad vorbelegt; der Fokus liegt im Passwortfeld, Enter entsperrt. Nach einem abgelehnten Passwort oder einer falschen Schlüsseldatei wartet Keyrook vor dem nächsten Versuch zunehmend länger (höchstens 60 Sekunden) und zeigt einen Countdown. Eine fehlende, beschädigte oder gerade belegte Tresordatei wird ohne Wartezeit gemeldet.

Sperren in der Fensterleiste oder Strg+L (macOS: ⌘+L) sperrt sofort, auch während ein Vorgang läuft. Sperren verwirft ungespeicherte Eingaben, leert die Anzeige und die Zwischenablage und schließt offene Dialoge. Bereits begonnene Schreibvorgänge werden zu Ende geführt. Automatisches Sperren ist in Kapitel 13 beschrieben.

Beim Schließen des Fensters während eines laufenden Vorgangs (Speichern, Backup, Integritätsprüfung, Export) fragt Keyrook nach; Trotzdem beenden bricht ab, Abbrechen lässt das Fenster offen.

Die Oberfläche

Fensterleiste

Die Leiste in den Farben des Programmsymbols zeigt den Namen, nach dem Entsperren die Warnliste mit ihrer Zusammenfassung (Kapitel 12), den Wechsel zwischen heller und dunkler Darstellung, Einstellungen, Info (Version, Tastenkürzel, Update-Prüfung) und Sperren.

Suchfeld, Chips und Filter

Unter der Leiste liegt das Suchfeld (Strg+F). Daneben öffnet Daten das Menü für Backups, Transfer und Zugang, Kunden, Projekte und Vorlagen die Verwaltung dieser Stammdaten, Neuer Eintrag (Strg+N) und Aus Vorlage … legen Einträge an, Tastenkürzel zeigt die Übersicht.

Darunter schalten Aktive Einträge und Papierkorb (mit Anzahl) die Ansicht um. Die Chips Favoriten, Zuletzt verwendet und Verborgene Felder durchsuchen schalten ihre Optionen. Sobald der Tresor Kunden oder Projekte hat, stehen die Auswahllisten Kunde und Projekt direkt neben den Chips; Weitere Filter zeigt Typ, Tag, Ablauf und Sortierung und bleibt offen, solange einer davon vom Standard abweicht. Filter zurücksetzen stellt die aktive Liste in Titelreihenfolge wieder her und leert die Suche.

Liste und Detailansicht

Jede Karte zeigt ein farbiges Typsymbol, Titel, Typ, Kunde und Projekt, sichtbaren Benutzernamen und Adresse, Ablaufdatum, Warn- und Tag-Badges und die Schnellaktionen (Abschnitt 5.5). Bearbeiten steht neben dem Text, weitere Aktionen (Duplizieren, Als Vorlage speichern, In den Papierkorb) im Menü ⋮. Vor dem Titel steht der Favoritenstern ☆/★, links ein Kästchen für Sammelaktionen.

Ist das Fenster mindestens 900 dp breit, erscheinen Liste und Detailansicht des ausgewählten Eintrags nebeneinander; in schmaleren Fenstern öffnen Sie Einträge über Bearbeiten. Die Detailansicht ist schreibgeschützt und zeigt Metadaten, Ports, Protokolle, SSH-Schlüsseltyp, zugeordnete Server, Registrar-Login einer Domain, Anzahl der Verlaufsversionen und jedes Feld mit Beschriftung, dann die Notizen:

  • Nicht maskierte Felder stehen im Klartext. Maskierte Felder und Notizen erscheinen als Punkte; Anzeigen zeigt einen Wert, bis Verbergen gedrückt wird. Angezeigte Werte werden automatisch wieder maskiert, wenn ein anderer Eintrag gewählt, der Eintrag gespeichert, der Editor geöffnet, das Layout gewechselt, das Fenster minimiert oder deaktiviert oder der Tresor gesperrt wird.
  • Kopieren kopiert einen Wert, ohne ihn zu zeigen, mit Ablaufzeit der Zwischenablage. Öffnen öffnet URL-Felder nach Prüfung des Links.
  • Servereinträge bieten den SSH-Befehl, SFTP-Einträge den SFTP-Befehl; das Passwort ist nie Teil davon.

Die Liste hat immer einen ausgewählten Eintrag (farbiger Rahmen, dicker bei Tastaturfokus). Eine neue Suche oder ein geänderter Filter wählt das erste Ergebnis. Verschwindet der ausgewählte Eintrag aus der Liste, springt die Auswahl auf den nächsten, sonst auf den vorigen. Suche, Filter und Auswahl bleiben über eine Bearbeitung hinweg erhalten.

Jeder Eintrag hat außerdem Titel, Kunde, Projekt, Tags, Notizen (verschlüsselt), ein optionales Ablaufdatum und einen Favoritenstern.

Eintrag anlegen

  • Neuer Eintrag (Strg+N) übernimmt Typ, Kunde und Projekt aus dem aktuellen Listenfilter. Ohne Typfilter wird der Typ des zuletzt angelegten Eintrags verwendet, sonst Web-Login. Ein Typwechsel im Editor behält Werte gleich benannter Felder (etwa Benutzername und Passwort).
  • Aus Vorlage … listet die Vorlagen des Tresors und die mitgelieferten Vorlagen Mailpostfach (IMAP und SMTP) (IMAP 993, SMTP 465, TLS) und Datenbank (Host, Port, Datenbank, Benutzername, maskiertes Passwort). Vorlagen enthalten nie Werte (Kapitel 7.3).
  • Duplizieren im Kartenmenü öffnet einen neuen Eintrag „… (Kopie)“ mit Typ, Feldaufbau, Ports, Tags, Kunde, Projekt und sichtbaren Werten. Passwörter, private Schlüssel, TOTP-Secrets, Notizen und Ablaufdatum werden nicht kopiert. Gespeichert wird erst mit Speichern.

Der Editor

Der Editor nutzt das ganze Fenster und beginnt mit dem Fokus im Titel. Alle Felder außer SSH-Schlüsselmaterial, DNS-Notizen und mehrzeiligen Werten sind einzeilig, sodass Tab zum nächsten Element springt. Strg+S speichert, Esc bricht ab; bei ungespeicherten Änderungen fragt Keyrook (Weiter bearbeiten hat den Fokus, Enter behält den Entwurf, Verwerfen verwirft ihn).

  • Verborgen. Jedes Feld kann einzeln maskiert werden. Maskierte Werte erscheinen in Liste, Detailansicht, Berichten und Suche nie im Klartext.
  • Kunde und Projekt. Die Listen enden mit + Neuer Kunde… und + Neues Projekt…: Sie fragen nach einem Namen und legen Kunde oder Projekt zusammen mit dem Eintrag im selben Speichervorgang an; Abbrechen verwirft beides. Die Wahl eines Projekts setzt dessen Kunden.
  • Tags. Durch Komma getrennt, höchstens 100 je Eintrag, je höchstens 256 Zeichen.
  • Ablaufdatum. Akzeptiert 2026-12-31, 31.12.2026, 1.2.2026 und 31.12.26 (zweistellige Jahre bedeuten 2000 bis 2099). Unmögliche Daten werden abgelehnt. +1 Jahr setzt ein Jahr nach dem eingegebenen Datum oder nach heute; Löschen entfernt das Datum.
  • Ports. Ganze Zahlen von 1 bis 65535; für Transfer, Server und jeden aktiven Mail-Endpunkt ist ein Port Pflicht.
  • Passwort generieren. Füllt das Passwortfeld mit einem Klick aus den gemerkten Generator-Einstellungen; Generator-Optionen öffnet Voreinstellungen, Länge, Zeichenklassen und Passphrasen (Kapitel 8).

Der Editor prüft während der Eingabe und markiert jedes betroffene Feld mit eigener Meldung: fehlender oder zu langer Titel (höchstens 4096 Zeichen), zu viele oder zu lange Tags, zu lange Werte oder Notizen, ungültiges Ablaufdatum, leerer oder ungültiger Port, ein nicht akzeptiertes TOTP-Secret, doppelte oder zu lange eigene Feldnamen. Speichern mit offenen Problemen speichert nichts und zeigt eine Zusammenfassung über den Buttons.

Verlauf

Jede Bearbeitung behält bis zu 500 frühere Feldstände mit Zeitstempel; kommen mehr zusammen, entfallen die ältesten. Der Verlauf zeigt verborgene Felder maskiert und bietet je Wert einen Kopieren-Button mit der üblichen Ablaufzeit. Tag-Änderungen, Favoriten und Papierkorbvorgänge erzeugen keine Verlaufsversionen; sie halten nur Feldwerte fest. Der Verlauf ist auch die Grundlage für die Warnung „altes Passwort“ (Kapitel 12).

Schnellaktionen

Ohne den Editor zu öffnen, kopieren die Buttons einer Karte Benutzername, Passwort (bei SSH-Schlüsseln die Passphrase), Host (Server, Transfer, erster Mailserver, Domain) sowie den SSH- oder SFTP-Befehl und öffnen die URL von Web- und Panel-Einträgen. Buttons erscheinen nur, wenn das Feld einen Wert hat; der Befehls-Button nur, wenn Host, Port und Benutzername einen gültigen Befehl ergeben. Eigene Datensätze (auch Bitwarden- und KeePass-Importe) werden über ihre Feldnamen erkannt: username, user oder Benutzername; password, Passwort oder passphrase (sonst das erste verborgene Feld); url, url1, uri oder host.

Die gleichen Aktionen liegen auf Strg+C (Passwort), B (Benutzername), T (TOTP-Code), U (URL öffnen), D (Host) und K (SSH/SFTP-Befehl) und wirken auch direkt aus dem Suchfeld auf den ausgewählten Eintrag. Hat der Eintrag kein passendes Feld, erscheint ein Hinweis und nichts wird kopiert. Geheime Werte werden in der Liste nie angezeigt.

Papierkorb

In den Papierkorb (auch Entf, macOS auch ⌫) fragt zuerst nach. Einträge im Papierkorb lassen sich jederzeit mit Wiederherstellen zurückholen; sie zeigen nur Metadaten und nicht maskierte Felder. Endgültig löschen entfernt einen Eintrag mit seinem gesamten Verlauf, Papierkorb leeren alle Einträge im Papierkorb, auch die von Filtern ausgeblendeten. Beide Dialoge beginnen mit dem Fokus auf Abbrechen, sodass Enter allein nie löscht. Verweise anderer Einträge (SSH-Server-Zuordnung, Registrar-Login) auf den gelöschten Eintrag werden geleert.

Wichtig

Nach dem endgültigen Löschen sind ältere Backups der einzige Weg zurück, und die Aufbewahrungsregeln können diese Backups mit der Zeit entfernen.

Suchen und Finden

Volltextsuche und Feldsuche

Die Suche (Strg+F) durchsucht Titel, Tags, Notizen, Feldnamen, sichtbare Werte, Kunden- und Projektnamen und Ablaufdaten ohne Beachtung von Groß- und Kleinschreibung. Mehrere durch Leerzeichen getrennte Begriffe müssen alle auf denselben Eintrag passen. Verborgene Felder durchsuchen bezieht maskierte aktuelle Werte ein, ohne sie in den Ergebnissen zu zeigen. Der Verlauf wird nie durchsucht; Suchen laufen im Hintergrund auf einer Kopie und legen keinen Klartext-Index an.

Ein Begriff der Form präfix:wort durchsucht nur ein Feld:

PräfixDurchsucht
kunde: / customer:Kundenname (direkt oder über das Projekt)
projekt: / project:Projektname
host:Host von Server, Transfer, Mailserver, Domain oder die URL
user: / benutzer:Benutzername
typ: / type:Eintragstyp
tag:Tags

Beispiel: kunde:müller host:web01. Unbekannte Präfixe werden als normaler Text gesucht, und ein Feldbegriff erreicht nie einen verborgenen Wert. Bei der Standardsortierung nach Titel werden Treffer nach Relevanz geordnet: Titel, die mit dem Begriff beginnen, dann Titel, die ihn enthalten, dann Treffer in Kunde, Projekt, Tags, Host, URL oder Benutzername, zuletzt alle anderen. Favoriten stehen vor gleich relevanten Einträgen.

Arbeitsfluss

Strg+F, Teil des Titels tippen, dann direkt Strg+C, B, D oder K: Passwort, Benutzername, Host oder SSH-Befehl liegen in der Zwischenablage, ohne das Suchfeld zu verlassen. ↓ oder Enter wechseln in die Liste, Esc leert die Suche.

Filter und Sortierung

Filtern lässt sich nach Typ, Kunde, Projekt, Tag und Ablauf (abgelaufen; heute bis in 30 Tagen; ohne Datum). Sortiert wird nach Titel, letzter Änderung oder frühestem Ablauf; Einträge ohne Datum stehen dabei zuletzt. Die Kundenwahl begrenzt die angebotenen Projekte. Auswahllisten mit mehr als acht Optionen beginnen mit einem Suchfeld: Tippen grenzt ein, Enter wählt die einzig verbliebene Option.

Favoriten und zuletzt verwendet

Der Stern ☆/★ vor dem Titel markiert einen Eintrag als Favorit; der Chip Favoriten zeigt nur Favoriten. Die Markierung wird im Eintrag gespeichert, ist kein Tag und bleibt bei Backups, Exporten und Importen erhalten. Zuletzt verwendet zeigt die bis zu zehn Einträge, die in dieser Sitzung zuletzt bearbeitet, kopiert oder geöffnet wurden, neueste zuerst. Diese Liste existiert nur im Speicher und ist nach dem Sperren leer.

Sammelaktionen

Jede Karte hat ein Kästchen; Leertaste markiert den ausgewählten Eintrag, Strg+A alle gelisteten. Über der Liste erscheinen dann die Anzahl und diese Aktionen:

  • Ausgewählte in den Papierkorb (aktive Liste) bzw. Ausgewählte wiederherstellen (Papierkorb)
  • Tag hinzufügen und Tag entfernen
  • Als Favoriten markieren / Favoritenmarkierung aufheben
  • Kunde/Projekt zuweisen: setzt Kunde und Projekt aller markierten Einträge in einem Speichervorgang; „–“ hebt eine Zuordnung auf

Jede Sammelaktion ist eine Tresorrevision und gilt für alle markierten Einträge oder, wenn einer nicht geändert werden kann, für keinen. Markierungen gehören zur aktuellen Suche: eine neue Suche oder ein geänderter Filter hebt sie auf, sodass eine Aktion nie einen Eintrag trifft, der nicht angezeigt wird.

Kunden, Projekte und Vorlagen

Kunden, Projekte und Vorlagen neben dem Suchfeld blendet den Verwaltungsbereich über der Liste ein. Das Feld für einen neuen Kunden hat den Fokus; Enter legt an. Ein Eintrag gehört zu seinem eigenen Kunden oder, ohne eigenen, zum Kunden seines Projekts. Diese Regel gilt für den Kundenfilter und alle Berichte.

Kunden

Ein Kunde hat einen Namen (höchstens 4096 Zeichen) und optional Ansprechpartner, E-Mail, Telefon, Website sowie Notizen (vertraulich). Die Prüfungen sind großzügig, aber begrenzt: eine E-Mail braucht ein @ und eine Domain mit Punkt, Telefonnummern bestehen aus Ziffern, Leerzeichen und + ( ) . / -, Websites haben keine Leerzeichen und nutzen http:// oder https://. Kontaktdaten erscheinen in der Kundenübersicht; die vertraulichen Notizen sind verschlüsselt und tauchen in keinem Bericht auf.

Projekte

Ein Projekt hat Name, Kunde und optional eine mehrzeilige Beschreibung sowie vertrauliche Notizen. Wird der Kunde eines Projekts geändert, wandern alle seine Einträge (auch im Papierkorb) und die Vorlagen, die dieses Projekt voreinstellen, in einem Speichervorgang mit. Löschen … ist nur möglich, wenn kein Eintrag und kein Projekt mehr auf den Kunden oder das Projekt verweist; die Rückfrage beginnt mit dem Fokus auf Abbrechen.

Vorlagen

Eine Vorlage stellt für einen neuen Eintrag Typ, Feldaufbau (welche Felder, welche maskiert, welche eigenen Felder Links sind), Standard-Tags und optional Kunde und Projekt voreins. Sie enthält niemals Werte, Passwörter, Notizen, Ports oder Verweise. Als Vorlage speichern im Kartenmenü oder in der Detailansicht fragt nach einem Namen (vorgeschlagen wird der Titel) und lässt den Eintrag unverändert. Aus Vorlage … öffnet einen neuen Eintrag „Neuer Eintrag aus Vorlage ‚…‘“ mit leeren Werten. Vorlagen werden am Ende des Verwaltungsbereichs als Vorlage löschen: … gelistet; das Löschen ändert keine daraus erzeugten Einträge. Vorlagen liegen verschlüsselt im Tresor und sind Teil verschlüsselter und Keyrook-JSON/CSV-Exporte.

Passwörter, TOTP und SSH

Passwortgenerator

Der Generator erzeugt 12 bis 256 Zeichen aus wählbaren Zeichenklassen; jede gewählte Klasse kommt mindestens einmal vor, alle solchen Passwörter sind gleich wahrscheinlich. Drei Voreinstellungen:

VoreinstellungZeichenWofür
StandardAlle Sonderzeichen !@#$%^&*()-_=+[]{}:,.?, 12 bis 256 ZeichenWeb-Logins, Panels
Shell/FTP-sicherNur -, _ und . als SonderzeichenShells, URLs, FTP/SFTP-Clients, Konfigurationsdateien ohne Quoting
Max. 16 ZeichenAlle Sonderzeichen, 12 bis 16 ZeichenAlte Panels, die längere Passwörter kürzen oder ablehnen

Keine verwechselbaren Zeichen lässt 0 O o 1 l I | 5 S 2 Z 8 B weg und kombiniert sich mit jeder Voreinstellung; wählen Sie dann eine größere Länge. Die zuletzt verwendete Voreinstellung, Länge und Zeichenwahl werden in den Einstellungen gemerkt, sodass Passwort generieren im Editor mit einem Klick arbeitet.

Passphrasen

Passphrasen werden aus einer von Ihnen gewählten, geprüften Wortliste erzeugt (UTF-8, bis 6,5 MB, 1024 bis 65536 verschiedene Wörter aus Buchstaben mit 2 bis 32 Zeichen, eines je Zeile). Trennzeichen sind Bindestrich oder Leerzeichen. Die Wortzahl muss mindestens 60 Bit Auswahlentropie ergeben: sechs Wörter bei Listen unter 4096 Wörtern, sonst fünf. Keyrook liefert keine Wortliste mit. Nach der ersten Nutzung merkt sich Keyrook Pfad, Wortzahl und Trennzeichen (nie den Inhalt); Passphrase mit gespeicherter Wortliste erzeugen liest die Liste erneut, Wortliste vergessen entfernt den Pfad.

TOTP-Codes

Web-Logins mit TOTP-Secret erzeugen zeitbasierte Einmalcodes nach RFC 6238. Das Feld akzeptiert ein Base32-Secret, wie es Dienste unter „Schlüssel manuell eingeben“ zeigen (Groß-/Kleinschreibung, Leerzeichen und Bindestriche egal; SHA-1, 6 Stellen, 30 Sekunden), oder eine otpauth://totp/…-URI aus einem QR-Code mit secret und optional algorithm (SHA1, SHA256, SHA512), digits (6 bis 8) und period (15 bis 120 Sekunden). Ungültige Secrets zeigt der Editor als Ungültiges TOTP-Secret; ein neu eingegebenes muss korrigiert werden, ein bereits gespeichertes (etwa aus einem Import) blockiert das Speichern nicht.

In der Detailansicht ist TOTP-Code maskiert; Anzeigen zeigt den aktuellen Code mit Restsekunden und Balken. Kopieren, die Schnellaktion TOTP-Code kopieren und Strg+T kopieren einen frisch berechneten Code, nie das Secret; der Hinweis nennt die verbleibende Gültigkeit. Lehnt ein Dienst Codes ab, prüfen Sie Systemzeit und Zeitzone.

SSH-Schlüssel

Keyrook erzeugt Ed25519- und RSA-4096-Schlüssel mit einer Passphrase von mindestens 12 Zeichen. Importiert werden eingefügte OpenSSH-, unterstützte PEM- und PuTTY-PPK-Schlüssel (Version 2 und 3; none und aes256-cbc, Argon2 für Version 3) und unter einer neuen Passphrase neu verschlüsselt. Bei PPK-Dateien wird vor der Verarbeitung der MAC geprüft, danach das Schlüsselpaar. Der öffentliche Schlüssel wird als geprüfte authorized_keys-Zeile in eine neue Datei exportiert. Für PPK-Dateien außerhalb dieser Grenzen beschreibt die Online-Dokumentation die manuelle Umwandlung mit PuTTYgen; Keyrook startet PuTTYgen nicht und übergibt ihm keine Geheimnisse. Keyrook öffnet nie eine SSH-Verbindung.

SSH- und SFTP-Befehle

Servereinträge liefern ssh -p <Port> <Benutzer>@<Host>, SFTP-Einträge den entsprechenden sftp-Befehl, als Text für PowerShell oder POSIX-Shells (nicht für die Windows-Eingabeaufforderung). Enthalten sind nur Host, Port und Benutzername: kein Passwort, kein Schlüssel, kein Startverzeichnis. Hosts müssen ASCII-DNS-Namen (Punycode für internationale Namen) oder IPv4/IPv6-Literale sein, Benutzernamen bis 64 ASCII-Zeichen aus Buchstaben, Ziffern, Unterstrich, Punkt und Bindestrich. Andere Formen werden abgelehnt statt in Shell-Text eingefügt. Keyrook führt den Befehl nie aus.

Links öffnen

Gespeicherte Links öffnen sich nur nach einem Klick (oder Strg+U). Akzeptiert werden nur HTTP/HTTPS-Adressen mit Host; eingebettete Benutzer/Passwörter, Steuerzeichen und ungültige Ports werden abgelehnt. Die Adresse wird dem Systembrowser übergeben; Keyrook selbst löst sie beim Prüfen nicht auf.

Backups und Export

Automatische Backups

Wählen Sie nach dem Entsperren unter Daten → Backup-Ordner einen bestehenden Ordner und bestätigen Sie die Aufbewahrung: Anzahl der jüngsten Versionen (1 bis 1000, Vorgabe 30) und zusätzliche Tagesvertreter (0 bis 3660, Vorgabe 30; 0 schaltet die Tagesregel ab). Beide Regeln gelten zusammen. Ab dann sichert jeder Speichervorgang zuerst die vorherige Revision in den Ordner, bevor die Tresordatei ersetzt wird. Schlägt das Backup fehl, wird nicht gespeichert; beheben Sie den Ordnerzugriff. Ältere Backups außerhalb der Regeln werden erst nach einem geprüften neuen Backup entfernt; lässt sich eines nicht löschen, meldet Keyrook die Anzahl und versucht es beim nächsten Mal erneut.

Ordner und Aufbewahrung werden je Tresordatei gemerkt und nach jedem Entsperren wieder angewendet; ein Hinweis zeigt den wiederhergestellten Ordner. Ist der Ordner nicht mehr nutzbar, öffnet sich der Tresor ohne Backups und bittet um neue Konfiguration. Backupdateien heißen <Tresor-ID>_<Zeit>_<Revision>_<UUID>.keyrook.bak und sind nur für Ihr Benutzerkonto lesbar.

Empfehlung

Legen Sie den Backup-Ordner auf ein anderes Laufwerk oder in einen synchronisierten Ordner, nicht neben die Tresordatei. Backups sind mit denselben Zugangsdaten verschlüsselt wie der Tresor zum Zeitpunkt des Backups.

Backup-Status und „Jetzt sichern“

Jetzt sichern kopiert den aktuell gespeicherten Tresor authentifiziert in den Backup-Ordner, mit denselben Aufbewahrungsregeln und ohne die Revision zu ändern. Backup-Status zeigt, ob Backups aktiv sind und welche Revision zuletzt gesichert wurde. Backups deaktivieren fragt nach und löscht keine vorhandenen Dateien.

Integrität prüfen

Integrität prüfen authentifiziert die gespeicherte Tresordatei und jedes verwaltete Backup des offenen Tresors im Backup-Ordner mit den aktuellen Zugangsdaten, neueste zuerst. Die Prüfung ist strikt lesend. Jede Datei braucht eine vollständige Schlüsselableitung, daher kann sie dauern. Ergebnisse je Datei:

Backup wiederherstellen

Backup wiederherstellen fragt die Zugangsdaten des Backups ab und zeigt dessen Anzahl Einträge und Revision in einer Vorschau. Nach Bestätigung wählen Sie ein neues Ziel; der offene Tresor wird nie überschrieben. Die wiederhergestellte Datei ist ein eigener Tresor mit neuer Tresor-ID und Revision 0, sodass sich ihre Backups nie mit denen des Originals vermischen. Sperren Sie und öffnen Sie die wiederhergestellte Datei getrennt.

Verschlüsselt exportieren

Verschlüsselt exportieren erzeugt eine neue .keyrook-Datei mit ausdrücklich gewählten Zugangsdaten, allen Einträgen, Kunden, Projekten und Vorlagen, mit Revision 0 und neuer Tresor-ID. Dies ist das bevorzugte Format zur Weitergabe an Kollegen oder zum Umzug auf einen anderen Rechner.

Passwort oder Schlüsseldatei ändern

Passwort / Schlüsseldatei ändern bestätigt ausdrücklich, welche Faktoren ersetzt werden: bestehende Schlüsseldatei erneut wählen, um sie zu behalten; eine andere wählen, um sie zu ersetzen; Feld leer lassen, um sie zu entfernen. Der Tresor wird atomar neu verschlüsselt, vorher wird das konfigurierte Backup angelegt. Ältere Backups benötigen weiterhin ihre ursprünglichen Zugangsdaten.

Kundenberichte

Die Berichte im Menü Daten gruppieren aktive Einträge nach Kunden (eigener Kunde oder Kunde des Projekts). Sie zeigen nie Passwörter, private Schlüssel, Passphrasen, TOTP-Secrets, Notizen, Verlauf, Werte eigener Felder oder irgendein als verborgen markiertes Feld.

Kundenübersicht

Kundenübersicht listet jeden Kunden mit Kontaktdaten, Projekten und Beschreibungen, der Anzahl aktiver Einträge je Typ, den Domains mit Ablaufdatum und den Server- und Transfer-Einträgen mit Host und Port; zuletzt folgt Ohne Kunde. Ein verborgenes Feld erscheint als Verborgen. Die Übersicht wird schreibgeschützt angezeigt und nicht gespeichert.

Übergabeblatt

Übergabeblatt exportieren fragt nach einem Kunden und einer neuen .html-Datei und schreibt dessen aktive Einträge nach Typ gruppiert: Titel, Typ, Projekt, Tags, Ablaufdatum, Ports, Protokolle, SSH-Schlüsseltyp, verknüpfte Server und Registrar-Logins sowie, wenn nicht verborgen, URLs, Hosts, Benutzernamen, E-Mail-Adressen, Mailserver, Startverzeichnisse, Rollen, Betriebssysteme, Fingerprints, Domainnamen und Registrare. Die Seite ist eine einzelne Datei ohne Links, Skripte oder externe Ressourcen und lässt sich aus dem Browser drucken. Prüfen Sie sie vor der Übergabe.

Ablaufdaten exportieren

Ablaufdaten exportieren schreibt die Ablaufdaten aller aktiven Einträge mit Datum, Titel, Typ, Kunde, Projekt und (bei Domains) Domainname in eine neue Datei:

  • CSV: UTF-8, kommagetrennt, jedes Feld in Anführungszeichen; Zellen, die mit =, +, -, @ beginnen, erhalten ein führendes ', damit Tabellenprogramme sie nicht als Formel ausführen.

Warnliste und Datenleck-Abgleich

Was geprüft wird

Die Tresorprüfung läuft nach dem Entsperren, nach jeder Änderung und einmal täglich im Hintergrund auf einer Kopie, die danach gelöscht wird. Sie betrachtet aktive Einträge und meldet:

  • abgelaufen und laufen ab (heute bis in 30 Tagen)
  • schwach: kurze oder sich wiederholende Passwörter
  • mehrfach: dasselbe Passwort in mehreren Einträgen
  • alt: Passwort seit über 365 Tagen unverändert. Das Alter zählt ab der letzten Passwortänderung im Verlauf, nicht ab der letzten Titeländerung; Einträge ohne Verlauf (manche Importe) zählen ab ihrer letzten Änderung.
  • doppelt: ein anderer aktiver Eintrag gleichen Typs hat denselben Host oder dieselbe URL und denselben Benutzernamen (ohne Groß-/Kleinschreibung und abschließende Schrägstriche). Port und Passwörter werden nicht verglichen.
  • geleakt: Passwort in bekannten Datenlecks, nur nach einem Abgleich (unten)

Leere Passwörter werden nicht bewertet. Die Prüfungen sind lokale Heuristiken; ein Passwort ohne Warnung ist nicht automatisch stark.

Warnliste lesen

Warnliste in der Fensterleiste zeigt die Anzahl je Grund (zum Beispiel 2 abgelaufen, 1 laufen ab, 3 schwach, 2 mehrfach, 4 alt, 2 doppelt, 1 geleakt, oder keine; wird geprüft während des Laufs). Karten und Detailansicht tragen Marker, die nur den Grund nennen, nie einen Teil des Passworts. Ein Klick auf die Warnliste öffnet die Übersicht mit den betroffenen Titeln; ein Klick auf einen Titel wählt den Eintrag aus und setzt dafür nötigenfalls Suche und Filter zurück.

Abgleich mit bekannten Datenlecks

Passwörter mit bekannten Datenlecks abgleichen … oben in der Warnliste vergleicht Passwörter mit dem Dienst Pwned Passwords von Have I Been Pwned. Das geschieht nie von selbst:

  1. Keyrook berechnet lokal die SHA-1-Hashes der nicht leeren Passwörter aktiver Einträge (Passwortfelder, SSH-Passphrasen, eigene Felder namens password, passwort oder passphrase; nicht Verlauf oder Papierkorb). Noch wird nichts gesendet.
  2. Eine Rückfrage erklärt bei jedem Durchlauf, was gesendet wird: nur die ersten 5 Zeichen jedes Hashes an api.pwnedpasswords.com, wie viele Passwörter und Anfragen, dass der Dienst Ihre IP-Adresse sieht und dass nichts gespeichert wird. Abbrechen hat den Fokus.
  3. Nach … Anfragen senden zeigt die Liste den Fortschritt; Abbrechen, eine fehlgeschlagene Anfrage oder eine ungültige Antwort beenden den Lauf ohne Ergebnis.
  4. Betroffene Einträge erhalten den Grund Passwort in bekannten Datenlecks mit der Trefferzahl des Dienstes.

Die Ergebnisse bleiben nur im Speicher und verschwinden beim Sperren; ein bearbeiteter Eintrag verliert seinen Marker bis zum nächsten Abgleich.

Sperren und Einstellungen

Einstellungen in der Fensterleiste öffnet alle Voreinstellungen; sie wirken sofort und überleben Neustarts.

Sperre nach Inaktivität

Sperre nach Inaktivität bietet 1, 2, 5 (Standard), 10, 15 und 30 Minuten sowie 1, 2, 4 und 8 Stunden. Nur Tastatur- und Mauseingaben in Keyrooks eigenen Fenstern zählen als Aktivität; Arbeit im Terminal oder Browser lässt die Frist ablaufen. Die langen Fristen sind für ganztägiges Arbeiten an einem persönlichen Rechner mit Bildschirmsperre gedacht: eine Sperre oder ein Standby des Betriebssystems sperrt Keyrook weiterhin sofort, wo die Plattform das Ereignis meldet. Ein Standby wird zusätzlich an der Systemuhr erkannt, sodass der Tresor nach dem Aufwachen gesperrt ist, auch ohne Benachrichtigung.

  • Darstellung: System folgen, hell oder dunkel; der Button in der Fensterleiste wechselt direkt.

Barrierefreiheit

Keyrook ist mit Screenreadern über die Java-Accessibility-Bridge nutzbar: Narrator oder NVDA unter Windows (Java Access Bridge aktivieren, etwa mit jabswitch -enable), VoiceOver unter macOS und Orca unter Linux.

  • Wiederkehrende Schaltflächen nennen ihren Wert, zum Beispiel Passwort anzeigen, Passwort kopieren, URL öffnen. Anzeigen/Verbergen melden, ob ein Wert verborgen oder angezeigt ist; ein maskierter Wert wird als Passwort: verborgen gelesen, nicht als Punkte.
  • Kontrollkästchen und Optionsfelder bilden mit ihrer Beschriftung ein Element; die Feldoptionen Verborgen und URL-Feld nennen ihr Feld.
  • Der Favoritenstern wird mit Eintragstitel und Aktion angesagt; das Kästchen einer Karte heißt Auswählen plus Titel, die Anzahl markierter Einträge ist ein Live-Bereich. Fehler- und Hinweismeldungen sind Live-Bereiche, wo die Plattform das unterstützt.
  • Jedes Textfeld hat eine sichtbare Beschriftung, die auch sein zugänglicher Name ist. Die Fokusreihenfolge folgt der sichtbaren Reihenfolge; Dialoge übernehmen den Fokus beim Öffnen.

Skalierung (90 bis 150 %) und hoher Kontrast sind unter Einstellungen beschrieben (Abschnitt 13.4). Tastaturfokus und gedrückte Elemente sind im Hochkontrastmodus stärker hervorgehoben; fokussierte Textfelder behalten einen dicken, akzentfarbenen Rahmen.

Problembehebung

Das Entsperren wartet mit Countdown.
Nach abgelehnten Passwörtern wächst die Wartezeit bis auf 60 Sekunden. Ein erfolgreiches Entsperren oder ein Neustart setzt sie zurück. Sperren allein nicht.
„Schlüsseldatei hat die falsche Größe“.
Eine Schlüsseldatei muss genau 32 Bytes haben. Prüfen Sie, ob Sie die richtige Datei gewählt haben, und ob sie unverändert ist (etwa nicht von einem Editor mit Zeilenumbruch gespeichert).
Der Tresor öffnet sich ohne Backups und bittet um Konfiguration.
Der gemerkte Backup-Ordner ist nicht mehr erreichbar (Netzlaufwerk, Rechte, umbenannt). Ordner wieder bereitstellen oder unter Daten → Backup-Ordner neu wählen.
Speichern schlägt fehl, weil das Backup fehlschlägt.
Keyrook speichert nie ohne gelungenes Backup, solange Backups aktiv sind. Ordnerzugriff beheben oder Backups bewusst deaktivieren.
Ein Backup wird als „nicht authentifizierbar“ gemeldet.
Normal für Backups vor einer Passwort- oder Schlüsseldateiänderung. Prüfen Sie es mit Backup wiederherstellen und den damaligen Zugangsdaten. Trifft das nicht zu, behandeln Sie die Datei als beschädigt.
TOTP-Codes werden vom Dienst abgelehnt.
Systemzeit und Zeitzone synchronisieren. Prüfen Sie, ob der Dienst SHA-256, 8 Stellen oder eine andere Periode verlangt; diese Parameter stehen in der otpauth://-URI.
Der SSH-Befehl-Button fehlt.
Host, Port oder Benutzername sind leer oder ungültig (internationale Hostnamen als Punycode eingeben, Benutzername nur ASCII). Ein ungültiger Port zählt im Editor als ungespeicherte Änderung.
Keyrook sperrt mitten in der Arbeit.
Inaktivitätsfrist unter Einstellungen verlängern (bis 8 Stunden) und die Fensterregel auf minimiert wird oder nie setzen. Arbeit in anderen Programmen zählt nicht als Aktivität. Bildschirmsperre und Standby sperren weiterhin.
Unter Linux gibt es keinen Menüeintrag.
Auf Systemen ohne /usr/share/desktop-directories kann der Menüeintrag nicht registriert werden. Die Anwendung läuft trotzdem über /opt/keyrook/bin/Keyrook.
Ein Import wird abgelehnt.
Bei CSV: Kopfzeile eindeutig und nicht leer, höchstens 100 Spalten. Bei KeePass CSV: genau die erwarteten Spalten, sonst CSV mit Feldzuordnung verwenden. Bei KeePass XML: keine KDBX-Datei, sondern den XML-Export wählen. Ein Tresor nahe 64 MiB nimmt keinen Import mehr an.
Alle Voreinstellungen zurücksetzen.
settings.json im Konfigurationsverzeichnis löschen (Anhang). Tresore sind davon nicht betroffen.
„Der Arbeitsspeicher dieses Rechners reicht für diesen Tresor nicht aus“.
Sehr große Tresore brauchen viel Arbeitsspeicher (Anhang, Grenzen des Dateiformats). Die Tresordatei bleibt unverändert. Andere Programme schließen oder den Tresor auf einem Rechner mit mehr Arbeitsspeicher öffnen.
Eine ältere Keyrook-Version meldet den Tresor als ungültig.
Der Tresor wurde von Version 1.5.0 oder neuer umgewandelt. Auf diesem Rechner Keyrook aktualisieren oder die beim Umwandeln abgelegte Kopie ….schema-v2-r….keyrook.bak verwenden (Abschnitt 2.7).
Ein Tresor aus Keyrook 0.7 oder älter.
Er öffnet sich normal; beim ersten Speichern bleibt die alte Datei als <Tresor>.schema-v1-r<Revision>.keyrook.bak daneben liegen. Ältere Versionen können den konvertierten Tresor nicht mehr öffnen.

Tresordateien, Backups, Exporte und Schlüsseldateien werden mit Rechten nur für Ihr Benutzerkonto angelegt (Modus 0600 unter macOS und Linux, Besitzer-ACL unter Windows). Keyrook ersetzt beim Exportieren, Wiederherstellen und Anlegen nie eine vorhandene Datei.

Grenzen des Dateiformats

  • Tresordatei höchstens 256 MiB
  • Je höchstens 100.000 Einträge (einschließlich Papierkorb), Kunden und Projekte; höchstens 1.000 Vorlagen
  • Verlauf höchstens 500 Feldstände je Eintrag
  • Titel, Kunden- und Projektnamen höchstens 4096 Zeichen; Tags höchstens 100 je Eintrag, je 256 Zeichen; eigene Felder höchstens 100 je Eintrag
  • Feldwerte und Notizen höchstens 262.144 Zeichen
  • Suchanfragen höchstens 256 Zeichen

Bis Version 1.4 galten 64 MiB, je 10.000 Einträge, Kunden und Projekte und 100 Feldstände. Die Grenzen schützen davor, dass eine beschädigte oder manipulierte Datei den Rechner beim Öffnen überlastet.

Arbeitsspeicher

Keyrook entschlüsselt den Tresor vollständig in den Arbeitsspeicher und darf dafür bis zur Hälfte des eingebauten Speichers nutzen. Übliche Tresore mit einigen tausend Einträgen brauchen wenige hundert Megabyte. Ein Tresor mit 100.000 Web-Logins und kurzem Verlauf ist rund 200 MiB groß und braucht zum Öffnen und Speichern etwa 3 GiB; dafür sollte der Rechner mindestens 8 GB Arbeitsspeicher haben. Jedes Speichern schreibt die ganze Datei neu und legt vorher ein Backup an; planen Sie im Backup-Ordner entsprechend Platz ein.

Dieses Handbuch beschreibt Keyrook @VERSION@. Die vollständige, laufend aktualisierte Dokumentation (Desktop-Anleitung, Sicherheitseigenschaften, Dateiformat, Paketierung) liegt im Ordner docs des Projekts auf GitHub.
